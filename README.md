# אתר תרגול לבדיקות איכות: סטודיו נועה לעיצוב

אתר קטן של עסק בדיוני, "סטודיו נועה לעיצוב", שנבנה כדי לתרגל בדיקות איכות לאתרים. יש בו דף נחיתה שמגיעים אליו ממודעה (עם UTM), חנות קטנה עם שלושה מוצרים, סל, קופה שנעצרת לפני תשלום אמיתי, וטופס לקביעת שיחה.

באתר הוטמנו בכוונה 10 באגים מהסוג שעסקים קטנים פוגשים כל יום. המטרה: להעלות עותק משלכם, להריץ עליו בדיקה, למצוא את הבאגים, לתקן ולבדוק שוב.

**חשוב:** באתר אין שום תשלום אמיתי. שלב "התשלום" הוא הדגמה שלא שולחת שום מידע לשום מקום. אל תזינו כרטיס אשראי אמיתי, השתמשו ב־`4242 4242 4242 4242`.

## 1. מעלים עותק משלכם ל־Vercel

[![Deploy with Vercel](https://vercel.com/button)](https://vercel.com/new/clone?repository-url=https%3A%2F%2Fgithub.com%2FYaakovTzedek%2Fqa-practice-site&project-name=qa-practice-site&repository-name=qa-practice-site)

1. לוחצים על הכפתור **Deploy** למעלה ומתחברים עם GitHub.
2. Vercel יוצר לכם עותק פרטי של הריפו בחשבון GitHub שלכם ומעלה את האתר. לא צריך לשנות שום הגדרה.
3. אחרי דקה מקבלים כתובת בסגנון `https://qa-practice-site-xxxx.vercel.app`. זה האתר שלכם לתרגול.

התוכנית החינמית של Vercel מספיקה לגמרי.

## 2. מאמתים את האתר בחשבון Persqo שלכם

כדי ש־Persqo יבדוק את האתר, צריך להוכיח שהוא שלכם. הדרך הפשוטה היא קובץ אימות.

1. ב־Persqo מוסיפים אתר חדש ומדביקים את הכתובת שקיבלתם מ־Vercel.
2. Persqo מציג טוקן אימות. מעתיקים אותו.
3. בוחרים אחת משתי הדרכים:
   - **דרך GitHub (הכי פשוט):** בריפו שלכם פותחים את הקובץ `public/.well-known/persqo.txt`, לוחצים על העיפרון, מוחקים את כל מה שכתוב בו ומדביקים רק את הטוקן. שומרים (Commit). Vercel מעלה את האתר מחדש לבד תוך דקה.
   - **דרך Vercel:** בפרויקט ב־Vercel נכנסים ל־Settings ואז Environment Variables, מוסיפים משתנה בשם `PERSQO_TOKEN` עם הטוקן, ואז ב־Deployments לוחצים Redeploy.
4. בודקים שהקובץ עלה: פותחים בדפדפן `https://הכתובת-שלכם/.well-known/persqo.txt`. צריך לראות רק את הטוקן, בלי שום טקסט נוסף.
5. חוזרים ל־Persqo ולוחצים על אימות.

## 3. בודקים, מתקנים, בודקים שוב

1. מריצים בדיקה ב־Persqo על האתר שלכם ורושמים מה נמצא.
2. מתקנים כל ממצא (בעזרת Claude Code או ידנית, ההנחיות בהמשך).
3. מעלים את התיקון (Commit ו־Push, ו־Vercel מעלה לבד) ומריצים בדיקה חוזרת על אותו ממצא.

את הרשימה המלאה של הבאגים, עם הסבר לכל אחד, תמצאו ב־[BUGS.md](BUGS.md). כדאי לפתוח אותה רק אחרי הבדיקה הראשונה.

## 4. מתגי התיקון

כל באג נשלט על ידי דגל בקובץ `src/fixes.js`:

```js
export const FIXES = {
  cookieBanner: false,
  adPrice: false,
  // ...
};
```

`false` אומר שהבאג חי. משנים ל־`true`, שומרים ומעלים, וקיבלתם את הגרסה המתוקנת. זה שימושי כשרוצים להראות "לפני ואחרי" בלי לכתוב קוד.

אפשר גם להדליק תיקונים בלי לגעת בקוד, דרך משתנה סביבה בזמן הבנייה:

```bash
VITE_FIXES=all npm run build                 # הכל מתוקן
VITE_FIXES=vatTotal,adPrice npm run build    # רק שני תיקונים
```

ב־Vercel מוסיפים את `VITE_FIXES` ב־Environment Variables ועושים Redeploy.

## 5. לתקן עם Claude Code

פותחים את התיקייה של הריפו ב־Claude Code ומדביקים את ההנחיה שמתאימה לממצא. כל הנחיה מתארת את התסמין, כמו שבודק היה מדווח עליו, ומבקשת תיקון אמיתי בקוד.

**1. באנר העוגיות מכסה את כפתור ההוספה לסל בטלפון**
```
בטלפון ברוחב 390 פיקסלים, בעמוד /product?id=branding, באנר העוגיות מכסה את הכפתור "הוספה לסל" שדבוק לתחתית המסך ואי אפשר ללחוץ עליו. תקן כך שהכפתור תמיד יהיה נגיש כשהבאנר פתוח, בלי להסתיר את הבאנר. אחרי התיקון הרץ npx playwright test -g "cookie" עם EXPECT_FIXED=cookieBanner.
```

**2. המחיר במודעה לא תואם למחיר בעמוד המוצר**
```
דף המבצע /offer מבטיח את חבילת המיתוג ב־1,990 ש"ח, אבל עמוד המוצר, הסל והקופה מציגים 2,490 ש"ח. תקן כך שמחיר החבילה בחנות יהיה מחיר המבצע, ושהמחיר יוגדר במקום אחד בלבד.
```

**3. התוספת נכנסת לסל פעמיים**
```
בעמוד /product?id=branding, כשמסמנים את התוספת "קבצי מקור פתוחים" ולוחצים "הוספה לסל", התוספת נכנסת לסל עם כמות 2. מצא למה ותקן כך שתיכנס פעם אחת בלבד, גם אם מסמנים ומבטלים את התיבה כמה פעמים.
```

**4. הסכום הכולל עם מע"מ שגוי**
```
בסל ובקופה כתוב "מע"מ 18%", אבל הסכום הכולל לא שווה לסכום הביניים כפול 1.18. לדוגמה עיצוב לוגו ב־890 ש"ח יוצא 1,041 במקום 1,050. תקן את חישוב המע"מ כך שיתאים ל־18% וכך שהשיעור יוגדר במקום אחד.
```

**5. תמונת ההירו כבדה**
```
תמונת ההירו בדף הבית שוקלת כמעט 8MB ומאטה את הטעינה, במיוחד בטלפון. החלף אותה בגרסת WebP קלה עם srcset לנייד ולמחשב, והוסף width ו־height כדי שהעמוד לא יקפוץ בזמן הטעינה. הקבצים hero-studio-1600.webp ו־hero-studio-800.webp כבר נמצאים ב־public/img.
```

**6. אין מחירון בתפריט**
```
לעמוד /pricing אפשר להגיע רק מהפוטר. הוסף קישור "מחירון" לתפריט הראשי, בין "חנות" ל"צור קשר", כך שיופיע בכל הדפים ובטלפון.
```

**7. שדות בלי תווית ותמונות בלי alt**
```
בטופס בעמוד /contact לשדות אין תווית (label), רק placeholder, ולשדה התאריך ולבחירת השירות אין שום תיאור. בנוסף, לתמונות המוצרים והעבודות בדף הבית, בחנות, בעמוד המוצר ובדף המבצע אין טקסט חלופי. הוסף label מקושר לכל שדה ו־alt תיאורי בעברית לכל תמונה.
```

**8. תמונה שמחזירה 404**
```
בדף הבית, באזור "עבודות אחרונות", תמונה אחת לא נטענת ומחזירה 404. מצא את הנתיב השגוי ותקן אותו לקובץ שקיים ב־public/img.
```

**9. כפתור מת בטלפון**
```
בטלפון ברוחב 390 פיקסלים, הכפתור "לקביעת שיחת היכרות" בדף הבית לא מגיב ללחיצה. בדוק איזה אלמנט יושב מעליו ותקן כך ששני כפתורי ההירו יהיו לחיצים, בלי לשבור את העיצוב.
```

## הרצה מקומית

צריך Node 20 ומעלה.

```bash
npm install
npm run dev        # http://localhost:5173
npm run build      # בנייה לתיקייה dist
```

## בדיקות אוטומטיות

בתיקייה `tests` יש בדיקת Playwright לכל באג. בפעם הראשונה מתקינים דפדפן:

```bash
npx playwright install chromium
npm run test:bugs     # מוודא שכל עשרת הבאגים קיימים
npm run test:fixed    # בונה עם VITE_FIXES=all ומוודא שכולם תוקנו
```

אפשר להריץ את הבדיקות גם על האתר החי שלכם:

```bash
BASE_URL=https://הכתובת-שלכם.vercel.app npx playwright test
```
